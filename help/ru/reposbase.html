Принцип работы репозитория

Для OvGME репозиторий — это просто веб-сервер (HTTP), отдающий XML-данные особой структуры со сведениями о модах для загрузки. Не путайте две вещи: сервер репозитория и место, откуда загружаются сами моды.

Обмен данными с репозиторием

Механизм репозиториев OvGME очень прост: веб-сервер размещает XML-файл, доступный по определённому адресу, как любая другая веб-страница; OvGME запрашивает этот файл у HTTP-сервера, разбирает его и узнаёт, какие моды доступны и откуда их можно загрузить.

Сервер репозитория

Сервер репозитория должен быть стандартным сервером HTTP 1.1 — по сути, это основной стандарт, используемый в вебе. Иными словами, сервер репозитория — это обычный веб-сайт, отдающий XML-файл, совместимый с OvGME. Единственное требование — OvGME должен иметь доступ к этому XML-файлу через Интернет по указанному URL.

Коротко: если XML-файл открывается в вашем браузере, его откроет и OvGME — значит, это «репозиторий OvGME».

Какой URL сообщать пользователям

Если на сервере лежит обычный XML-файл, пользователям нужно сообщить полный URL этого файла — с расширением «.xml» на конце или без него. Если в конце URL нет «.xml», OvGME добавит его автоматически.

Например, если полный URL XML-файла такой:
"http://www.example.com:8080/repository/game1.xml"

то для OvGME также подойдёт URL:
"http://www.example.com:8080/repository/game1"

OvGME поддерживает все стандартные форматы URL — с протоколом и портом или без них. Примеры поддерживаемых форматов:
http://www.example.com/folder/repository
www.example.com/folder/repository
www.example.com:8081/folder/repository
http://www.example.com:8081/folder/repository
Примечание: если порт не указан, используется стандартный порт HTTP 80.

Динамически формируемые XML-данные

OvGME поддерживает кодирование передачи chunked для простых запросов HTTP GET (но не для загрузки файлов). Иными словами, OvGME может получать XML-данные с любой динамически формируемой веб-страницы, например PHP или ASP.

Однако в этом случае URL репозитория должен позволять OvGME понять, что это не обычный XML-файл (чтобы не добавлять к URL расширение «.xml»). Для этого URL должен:
  • либо быть полным адресом файла с расширением «.php», «.asp» или «.aspx»;
  • либо содержать символ «?», типичный для динамических запросов.
Примеры допустимых URL динамически формируемых репозиториев:
http://www.example.com/repository.php
http://www.example.com/repo.asp
http://www.example.com?game=1&type=2
Динамическое формирование XML позволяет владельцам репозиториев использовать настоящие базы данных и собственные генераторы XML.

XML-данные репозитория

Для OvGME репозиторий — это всего лишь XML-файл, описывающий, какие моды доступны, некоторые полезные сведения о них и откуда их загрузить. Это своего рода мини-база данных; разница лишь в том, что XML-файл отдаёт веб-сервер.

Структура XML репозитория

OvGME ищет в полученных XML-данных определённую структуру, чтобы извлечь сведения о модах. Структура достаточно проста, чтобы XML репозитория можно было написать вручную в любом текстовом редакторе.

Кроме того, в OvGME есть инструменты для автоматического создания и проверки XML-файлов репозитория (см. ниже).

Пример типичного XML-файла репозитория:

<mod_list>

   <mod name="Dummy Mod A" version="1.1" url="www.toto.net/Mod%20A.zip">
   Dummy Mod A Description&#13;&#10;Version 1.1&#13;&#10;
   </mod>

   <mod name="Dummy Mod B" version="1.2" url="www.bubu.org/Mod%20B.zip">
   Dummy Mod B Description&#13;&#10;Version 1.2.2&#13;&#10;
   </mod>

</mod_list>

 Если вы раньше не видели XML, то заметите сходство с HTML: у них много общих правил синтаксиса. Эта справка не ставит целью объяснить все тонкости XML, но некоторые базовые технические моменты помогут понять структуру в целом.


В примере выше для наглядности разные элементы выделены цветом:

  • <фиолетовые> элементы называются «узлами»;
  • зелёные= элементы называются «атрибутами»;
  • "синие" элементы — строки, это значения атрибутов;
  • чёрные части — внутреннее содержимое узлов.
Структура узлов
В примере три узла: mod_list — корневой узел, а два узла mod — его дочерние узлы. Именно такую базовую структуру OvGME ищет в файле репозитория: один корень и несколько дочерних узлов, каждый из которых описывает мод. Количество узлов-описаний модов в XML репозитория не ограничено.

Атрибуты описания мода
Каждый узел описания мода должен иметь три атрибута: «name», «version» и «url». Здесь имена важны: OvGME ищет именно эти атрибуты и их значения.

Примечание: порядок атрибутов не важен — можно указать сначала url, а name в конце, это ни на что не влияет.
  • name — имя мода. Это имя во всех случаях идентифицирует мод, в том числе во внутренних алгоритмах OvGME при сравнении с локально установленными модами.

  • version — версия мода. Это значение используется, например, для сравнения с локально установленными модами (подробнее см. раздел «Версии модов»).

  • url — URL загружаемого файла. По этому адресу OvGME запрашивает zip-файл мод-архива. URL должен быть корректным HTTP-адресом.

Описание мода
Внутри узла описания мода можно (необязательно) указать описание мода — это чёрная часть в примере выше. Ограничений на размер и формат нет, но, как и в HTML, формат XML «не замечает» переводы строк внутри данных. В отличие от HTML, тег «<br>» использовать нельзя. Чтобы обозначить перевод строки в описании, его нужно закодировать специальной последовательностью «&#13;&#10;».

Примечание: эта последовательность буквально означает «вставить код ASCII возврата каретки (13); вставить код ASCII перевода строки (10)» — так называемую последовательность CRLF (Carriage Return Line Feed).

Генератор XML-источника

Чтобы упростить создание корректного XML-файла репозитория, в OvGME есть инструмент, который автоматически создаёт XML-источник, анализируя содержимое папки с модами (или указанной вами папки). Он берёт все корректные zip мод-архивы, проверяет наличие VERSION.txt и файла описания и собирает всё это в XML-код репозитория.
Чтобы открыть генератор XML-источника, откройте меню «Моды», выберите «Репозитории», затем «Создать XML-источник...»

Своя папка модов
Если флажок установлен, укажите существующую папку с корректными мод-архивами, по которым будет сформирован XML-список модов.
Если флажок не установлен, используется папка с модами текущей конфигурации.

Базовый URL ссылок для загрузки
Базовый URL для формирования ссылок на загрузку модов. Например, если указать базовый URL «http://www.example.com/public», ссылка для мода будет такой: «http://www.example.com/public/My%20Super%20Mod.zip».

Примечание: технически ссылки на загрузку не обязаны вести в одно место — можно использовать любые корректные URL, и у каждого мода может быть своя ссылка. Однако генератор XML создаёт только однотипные ссылки для всех модов. Если моды на самом деле размещены в разных местах, отредактируйте XML-источник вручную, заменив URL нужных модов.

Указав необходимые данные, нажмите кнопку «Создать XML», чтобы сформировать XML-код. Полученный текст можно отредактировать по своему усмотрению.

Наконец, когда XML-источник сформирован и отредактирован, сохраните его кнопкой «Сохранить XML...».

Проверка XML-источника

Чтобы убедиться, что XML-файл репозитория будет правильно разобран, в OvGME есть инструмент проверки любого XML-файла как источника репозитория. Чтобы открыть его, откройте меню «Моды», выберите «Репозитории», затем «Проверить XML-источник...». Автоматически откроется окно выбора проверяемого XML-файла.

Если разбор успешен, появится сообщение об успехе, а результат разбора будет показан в текстовой области вывода. В противном случае отобразится ошибка разбора.
